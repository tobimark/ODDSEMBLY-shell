> 用途：交给 ChatGPT 做视觉设计。本文只描述**现状事实**与**约束**，不含任何已实施的设计。
> 分支：`dev`　基准：`main@f2679ad`
>
> **v2 相对 v1 的变化**：v1 只覆盖了 Loom 画布。v2 补上了外围的 Agent 工作台外壳，
> 并**推翻 v1 的一个错误结论**（见 §0.2）。

## 0. 两条必须先说清的事

### 0.1 这个项目其实有两层界面

| 层 | 实现 | 尺寸 | 覆盖内容 |
|---|---|---|---|
| **A. 画布场景** | Pixi.js 8 / WebGL 纯矢量 | 设计空间 1472×1008，显示 730×548 | 织机、转盘、齿轮、布面、纱架 |
| **B. Agent 工作台外壳** | React 18 + CSS（DOM） | 客户区 1440×852（截稿 1453×865） | 标题栏、侧栏、导航条、四张指标卡、Agent 对话面板 |

两层是**各自独立实现**、拼在同一个窗口里的。改版必须同时考虑，否则会互相打架（见 §4）。

### 0.2 纠正 v1 的一个错误

v1 我写的是「你没有卡片墙、没有终端面板，所以已经和 CrommaCode 不同了」——**这是错的**。

那是只看了画布得出的判断。看了外壳之后的事实是：**外壳是按 CrommaCode 逐像素复刻的**，
文档原文就写着「像素级复刻 CrommaCode 界面」，并且为此建了截图比对与分区打分工具
（`shell/tools/diff.py`，指标叫 `CHROME SCORE`）。四张指标卡、模式标签行、终端面板、
265px 侧栏、圆角卡片，**全都在**。

所以真实情况是：

- 画布 = 已经演化出自己的样子（青灰单色，比 CrommaCode 更安静）。
- 外壳 = **仍然是一比一复刻**，是本次差异化的主要战场。

### 0.3 需要你知道的资产来源问题

外壳里有两样东西是从 CrommaCode 二进制里直接取出来的：

| 资产 | 位置 | 情况 |
|---|---|---|
| `Cromma Sans` 字体（Regular/Medium） | `shell/public/fonts/` | CrommaCode 自有字体，无公开许可 |
| 189 个图标 SVG | `shell/src/svg/icons.ts` / `uiIcons.ts` | 从二进制抠出的真实资产 |

`Maple Mono CN` 是开源的（OFL），可以放心留用。

我不是在提合规说教——**这件事直接和你的目标重合**：这两个资产既是最强的"像"的来源，
替换它们本身就是最有效的差异化手段。内部研究用没问题；如果产品要对外发布，建议替换。
设计时可以顺带把"替换成什么"一起考虑掉。

## 1. 项目是什么

**KUNLUNMETA Agent Visual Engine**：把 AI Agent 的工具调用变成一台竖织机的机械动作。

一次工具调用 = 织一针；五种工具各有固定颜色，织进布面。Agent 在干活，屏幕上就有一台织机在织布。

- 外壳承担"正常 Agent 工作台"的职能：项目树、会话、对话、工具调用记录、指标卡。
- 画布承担"把 Agent 的行为可视化"的职能。

## 4. 关键判断：两层必须共用一个隐喻

v1 我按画布单独给了四个方向。加上外壳后这个思路不成立了——如果画布是"藏图版"、外壳是"仪表盘"，
两层的语气会互相抵消，看起来还是拼贴。

**所以正确做法是先定一个"整机隐喻"，再让两层都服从它。** 下面四个是整机级的。

---

## 5. 四个整机隐喻（选一个深挖，不要都做）

### M1 — 图版与图框（Atlas Plate）

整个窗口是**一本图集的一页**：画布是图版，外壳是页边、图号、索引、页眉页脚。

- **画布**：保留现有机械插画，加图版编号与比例尺；下方加一行图注（caption）。
- **外壳**：去掉圆角卡片与胶囊按钮，改成印刷页边——细线、编号、页眉眼标、边注（marginalia）。
  四张指标卡 → 变成图版下方的四个"图例条目"，用引线连到画布对应部件。
- **与 CrommaCode 的区分**：它是一堆圆角面板；M1 是**没有圆角的一张纸**。
- **风险**：无圆角+密排在 1440×852 下容易显得单调，需要靠字号阶梯和留白撑住。
- **工作量**：中。主要动外壳的边框语言与卡片。

### M2 — 仪器机架（Instrument Rack）

整个窗口是**一台仪器的操作面**：画布是观察窗，外围是通道列表与读数。

- **画布**：现有机械可以更"被观察"——加观察窗的压边、玻璃反光的一点点暗示。
- **外壳**：侧栏 → 通道/信号列表（等宽、有通道号）；四张卡 → **一条连续的状态带**
  （不是四张独立卡，而是一行带刻度的读数，像机架上的表头）；AgentPanel → 通讯记录。
- **与 CrommaCode 的区分**：它把指标做成四张等大卡片（bento），M2 把指标**拉成一条带**，
  这是骨架级别的差别，一眼可辨。
- **风险**：状态带宽而扁，信息密度要重排；数值对齐要求高（等宽字体是优势）。
- **工作量**：中。Cards 一个区域重做 + 侧栏改名。

### M3 — 实验记录本（Lab Notebook）

整个窗口是**一本正在被写的记录本**：画布是贴上去的图版，对话是记录正文。

- **画布**：图版有贴纸感（轻微倾斜、纸边阴影极淡）；可以允许"手写"批注线。
- **外壳**：对话区变成记录正文（加大行距、页边批注放工具调用）；侧栏是目录（带页码）；
  四张卡 → 页脚的一行汇总字。
- **与 CrommaCode 的区分**：语气从"软件界面"变成"文档"，且天然解释了"为什么聊天和机器并列"。
- **风险**：手写感全靠字体，而我们**没有手写字体且不宜新增**（见 §6），只能用排版暗示。
- **工作量**：中大。

### M4 — 展台孤品（Single Exhibit）

几乎全屏是画布，外围全部收边。

- **画布**：放大到接近满窗，只留极窄边。
- **外壳**：侧栏与卡片收成可展开的边缘抽屉；对话做成右下角浮层（可收起）；
  标题栏压到 32px 甚至去掉菜单文字只留图标与字标。
- **与 CrommaCode 的区分**：**最彻底**。它是一堆面板围着画布，M4 是画布吞掉面板。
- **风险**：牺牲 Agent 工作台的日常可用性（重度对话/看文件时体验下降）；
  这是产品取舍，不只是视觉取舍，需要你拍板。
- **工作量**：大（要改布局与交互，不只是样式）。

**建议**：如果这个产品的定位是"展示 Agent 在织布"，选 **M4**，但要接受功能折损；
如果要当日常工具用，选 **M2**——它区分度够、风险最低，且不牺牲信息密度。
**M1** 是最"有文化"的，但最容易做成"更好看的同一件事"。

## 6. 必须保留的风格 DNA

你要求"风格还要保留"。翻成可执行的判断标准：

1. **暖白纸底**。不用深色主题、不用纯白、不用冷灰蓝。
2. **线表达结构**。结构用发丝线画，允许浅填充暗示体积，但面积要小。
3. **保留一道大圆弧母题**（现在是画面左上）。可换角度/位置，不可消失。
4. **空闲近乎静止**。不跑常驻循环动画；只有事件到达时局部动，弹簧插值，不用缓动曲线。
5. **HUD 与场景解耦**。HUD 固定高度、等宽数字、小标签大间距。
6. **单一进程色**（青 `#33CBCC` 负责"进行中"）；工具五色只做点缀与织物染色。
7. **中文与等宽混排**是这套界面的辨识度来源，保留。

## 7. 硬约束（设计者不得违反）

1. **不改功能**。事件状态机、12 槽索引、30° 步进、draft 织法（4 片综框、2/2 斜纹）、
   换新布逻辑、`src/live/` 实时链路都保持。
2. **不改工具色语义**。五色对应五工具，可调明度不可换色相。
3. **画布 0.496 缩放下必须可读**：新文字 ≥6.5px，有信息量的数字 ≥8px。
4. **不引入位图、外链、新依赖**。画布只能用 Pixi `Graphics` + `Text`；外壳只能用现有 CSS。
5. **字体不新增**。外壳可用 `Maple Mono CN`（OFL）；`Cromma Sans` 若要换，只能换成
   系统字体或 OFL 字体，且必须给出等宽/字宽的替代方案。
6. **HUD 字段名固定**：画布 `PICKS / QUEUE / SHED / MODE`；外壳的指标卡名称可改，
   但四个指标的含义（工具流 / 调用率 / Token 流速 / 后台进程）不能丢。
7. **不要"四张等大圆角卡片横排"**。这是 CrommaCode 最强的骨架签名——可以有四个指标，
   但排布方式必须换（参考 M1 的图例条目 / M2 的连续状态带 / M3 的页脚汇总）。
8. **不要"胶囊形标签页"**（NavBar 那个）。同样是签名元素，换成页眉字标、目录或通道号。
9. **新增颜色不超过 3 个**，且从现有色板派生（同色相调明度/饱和度）。

## 8. 需要 ChatGPT 交付的产物

按这个顺序、这个格式，不要直接给代码：

1. **四个整机隐喻各一句观感 + 3 个关键词**。
2. **选定一个**，并说明它对**画布**和**外壳**分别意味着什么（两层都要讲，不能只讲一层）。
3. **色板 token 表**：hex / 用途 / 是否新增（新增须说明从哪个现有色派生，总数 ≤3）。
4. **版式草图两份**：
   - 外壳：SVG（viewBox `0 0 1440 852`）画区块，标出 Sidebar 265 / Canvas 730.5 / Agent 411.5 的取舍。
   - 画布：SVG（viewBox `0 0 1472 1008`）。
5. **指标区重排方案**：四个指标在新隐喻下怎么放（这是区分度的关键，要具体到几何）。
6. **文案**：标题、模式签、指标名、空态提示（中英各一版）。
7. **改版说明 3–5 句**：为什么这样就与 CrommaCode 明显不同了。
