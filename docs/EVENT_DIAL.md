# 事件转盘（Loom Event Dial）— 动态转轮 + 固定读数窗

- **会动的是 12 槽索引鼓**：每个新工具组前进 30°；180 ms `easeInOutCubic`；
  同工具事件合并为 `×N`，不推轮；idle 零位移。
- **读数窗结构上不旋转**：V6 起是盘面静止结构上的 **245×100 固定窗**，水平、轴对齐；
  没有 rotation/parent-rotor 字段，只显示工具 / ×N / Sxx/12。
- **颜色=当前工具**：`ToolPalette` 取原版运行时采样色。
- 105 ms 显示延迟 → 180 ms 换卡 → 单卡约 2 s 停留；参数来源见研究 §6/§8/§9。

| 议题 | 原版（已观察） | 本实现 |
|---|---|---|
| 稳态 | 盘面零位移 | 转轮停在目标槽位 |
| 换卡 | 70–200 ms 卡片沿弧掠过 | 180 ms 索引步进 |
| 读数窗 | 环带扇段、固定位置 | **固定轴对齐读数窗**（文字水平、结构不转） |
| 转动件 | 仅共享刻度环相位 | 12 窗索引鼓可见转动 |
| 颜色 | 弧段=当前工具 | 同一段弧 + 当前卡窗着色 |
| ×N | 同工具调用聚合次数 | 同工具聚合；卡片 2 s 后消失但**分组保留**（12 s 组窗口），真实 Agent 跨步调用仍计为 ×N |
| Sxx/12 | 组序 / 运行时总数 | 槽位 / 12，10 组后回绕 |
| idle | 无卡、无动效 | `holdMs` 后清空、回 IDLE |

## 结构

```
EventDial.body (在织机后面)                 EventDial.front (压在织机上)
├── stator  环带/滚花/蓝弧/内鼓/夹块          └── readout
├── rotor   12 个环扇卡窗 + 5° 刻度               ├── panelSprite 245×100（单壳 + 凹窗）
│   └── slotTint 当前卡窗的细色边                 ├── typeText 49px bold
├── accent  37°–43° 工具色弧                      ├── multText ×N 30px
└── pointer 固定读头（座/臂/读数窗口）             └── stepText Sxx/12 26px
```

不变量：

1. **任何 Text 都不在 rotor 子树里**（水平文字只在非旋转层）。
2. 读数窗几何没有 rotation 字段；构造期定位在盘面局部 `(80,170)`、245×100；
   转盘整体 0.83 缩放不改变其“不旋转”性质；允许压在卡窗上方，但绝不随盘旋转。
3. 所有旋转件姿态 = `f(state.angleDeg)` 的纯投影；模型纯函数，可 node 直测。
4. “固定”指**设计空间**固定，不是 DOM 浮层。

## 状态机

```
IDLE ──event──► ARMING(105 ms) ──► MOVING(180 ms) ──► HOLD(≤2000 ms)
  ▲                                    │                    │
  │                                    └─ 同工具聚合：跳过 MOVING，×N++
  └──────────────── 超时清空 ◄──────────┴────────────────────┘
```

| 相位 | 进入 | 时长 | 行为 |
|---|---|---|---|
| `arming` | 新工具组 | 105 ms | 读数先更新；转轮不动 |
| `moving` | 延时到 | 180 ms | `easeInOutCubic` 到 `ordinal*30°` |
| `holding` | 到位 | 2000 ms（同工具续期） | 零位移；`×N` 就地递增 |
| `idle` | 超时 | — | 清空读数与卡窗叠色 |

`reducedMotion`：`armDelay=0, move=0`，角度瞬跳。

模型见 `atelier/dialModel.ts`；不读时钟、不用随机数，60/30 fps 与单次 1 s tick 终态一致。

### 分组（group）≠ 卡片（card）

真实 OpenCode 的连续同类调用发生在**不同模型步**里，实测间隔可达 2.4 s，超过卡片
2 s 的停留时间。若只按卡片生命周期聚合，两次 `read` 会分裂成两个槽位并要求真实场景
（验收 B）出现 `×2`，因此模型把两者分开：

| 概念 | 寿命 | 作用 |
|---|---|---|
| 卡片 `card` | `holdMs` = 2000 ms | 读数窗显示什么；过期后读数窗回 IDLE |
| 分组 `group` | `groupTimeoutMs` = 12000 ms | 槽位归属与 `×N` 计数 |

- 同一工具在组内再次到达：`×N++`，**转轮零位移**；若卡片已过期，读数窗以同一个
  槽位重新出现（不产生新的 30° 步进）。
- 其他工具到达，或超过 12 s 组窗口：关闭当前组，下一个工具开新组并前进 30°。
- 因此 `×N` 绝不会合并被其他工具隔开的事件（顺序即分组边界）。

## 已知边界

- 交互式 60fps 过渡轨迹未重新实测；180ms 是原版 70–200ms 的放大值。
- 原版读数窗绘制函数未定位，V6 是几何重构。
- ×N 是否跨 session 重置未知；按进程内当前组计数。
- `Sxx/12` 的 `12` 语义仍是推断；本实现采用 12 槽环。
- 铭牌文案为自创设计，不是原版观察。
