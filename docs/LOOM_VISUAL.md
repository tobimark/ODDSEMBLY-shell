# Loom 视觉：布料生长 · 浅色配色 · 转盘光路

本轮三处视觉改动。机械结构、转盘盘面、读数窗几何都没有重画，只改了布料的存在方式、
结构色和一条新增的光路。

---

## 1. 布料从零生长

**旧行为**：布面从第一帧就是完整的（`textile.ts` 固定画 73 行斜纹，只按 pick 数错位），
所以 idle 就是一块织好的布，看不出"织"的过程。

**现行为**：布从**卷取横梁**（`CLOTH.bottom = 830`）开始，每一针在织口铺一行，布边向上长。

| 项 | 值 |
|---|---|
| 一行 | 8 px（≈4 条纬线） |
| 满匹 | 55 行 ≈ 440 px（经线区约 80%） |
| 织口初始位置 | 830（贴横梁，梭子/筘就在最底部） |
| 织口终点 | 390（上横梁下方，筘不过梁） |
| 满匹之后 | **换新布**：下一针清空，从 0 重新织 |

关键实现：

- `Textile` 只画"已经存在的行"，画布其余部分透明；`scene` 用矩形 mask 裁到
  `[织口, 830]`，所以布面高度 = 行数 × 8。
- 布**排在经线之后、综框/筘/梭之前**：布盖住经线，但不遮住综框和筘——综框随布面
  上升被布逐渐埋掉，筘和梭始终在布前面。这是"布包住综框"的唯一自洽顺序。
- 织口位置驱动整个工作头：`head = 织口 − 698`。空布时工作头下沉 132 px 到横梁上方，
  满匹时上移 308 px。筘、梭、梭道、前综一起走；综框不动。
- 筘的伺服连杆行程超出曲柄可达范围时会**如实断开**（只在伺服上画曲柄），
  不再抛异常——这修掉了之前"行程一大画面就冻住"的问题。
- 取布阶段（phase .84→1）布边按 `takeup` 连续滑动 8 px，不是每针硬跳一格。

经线现在从**上横梁一直画到织口**（`WARP_H = 830 − 278`）。之前的空白就是"经线只画到
698、织口却降到 830"露出来的缝。

## 2. 浅色配色

参考机的实测色板（`loom_canvas_idle.png`）：97% 的像素在 `#F6F0EA`–`#FCFCF6`，
最深的结构线只到 `#746C64` / `#8C8478`，合计不到 0.3%。也就是说它是**浅底 + 发丝线**，
不是深色块。

因此把结构藏青 `#171C60` 整条替换成浅暖灰：

| 用途 | 旧 | 新 |
|---|---|---|
| 机架导轨 / 铭牌底色（`C.navy`） | `#171C60` | `#E1DACA` |
| 发丝线 / 小标签（`C.ink`、`F.ink`） | `#323953` / `#171C60` | `#7A6F62` / `#A8A08E` |
| 转盘蓝弧（`DIAL.blue` 描边、缺口线） | `#171C60` | `#C9C2B0` |
| 钢件面（`C.steel`） | `#919B9F` | `#CFC8B6` |
| 提花机针脚 / 沉降片 | `#576E74` | `#A9B2AD` |
| 铭牌文字（原白字压深底） | `#EEEFE9` / `#F8F7ED` | `#7A6F62`（浅底深字） |

工具色（`toolPalette.ts`：Read 蓝灰 / Bash 绿 / Edit 品红 / Write 琥珀 / Search 青）
保持不动，是画面里唯一的彩色。织物的经线纱色也把 4 个藏青换成暖灰，
纬线每针只压**一条 0.9 px 的工具色发丝线**（不再整行染色）。

## 3. 转盘 → 齿轮的光路

参考机从夹块到控制箱有一条**波纹柔性导管**，几何固定、只随事件变色（写/编辑类变橙黄）。
本轮按用户指定的走线做成"垂直折角"：从转盘左下**竖直向下**，到横梁下方**直角右折**，
接到齿轮组底座。

- 几何：`[(-34,548) → (-34,792) → (118,792) → (118,766)]`（三个卡箍 + 端盒）。
- 每个工具调用发一次光脉冲：`0.26 s` 跑完整条 260 px 管路，颜色 = 该调用的工具色，
  带 46 px 拖尾；同时最多 3 个脉冲，多出来的合并，不会无限堆积。
- 到达齿轮时**只辉光**（飞轮 + 两个齿轮各一圈 0.55 s 衰减的光），**不改变转速**——
  转速仍然只由投梭驱动。
- 折叠（`fold`）的调用也发光：光路是"事件到达"的反馈，与机械队列无关。

模型见 `atelier/conduit.ts`，纯几何 + 时间，不读全局时钟。

## 4. 织法：draft（2026-11-17 新增）

之前的布面是"固定 2/2 斜纹公式 + 每行染色"，也就是**贴图在长高**。现在改成由**开口计划**
（draft）生成，综框动作和布面交织使用同一份数据。

参考依据（`analysis/r3-static/loom-detail.md` §3.3、§5；
`CrommaCode-Loom场景动画-视觉映射.md` §7）：

| 参考机事实 | 本实现 |
|---|---|
| 一次调用 = `Shuttle → Needles/Lift → Dock → BeatUp → Lower → TakeUp/Stitch` | 现有 `mechanism` 的相位就是这五段 |
| `Needles/Lift` **选一组经线抬起**形成开口（不是全局两片翻转） | 四片综框，draft 每针选两片 |
| 布面由"织入的针"生成，亮度 0.75/0.875、色值上限 255 | warp/weft 两个面用两个亮度，工具色只做本体染色 |
| 提花机只做几何/相位计算，**无随机数** | draft 是常量表，无随机 |
| 布面行坐标 + 可视窗裁剪 + `TakeUp` 前移一行 | 我们按你的要求改成"向上生长"，行坐标仍由 picks 决定 |

实现：

- `atelier/draft.ts`：`DRAFT = { shafts: 4, rows: [[0,1],[1,2],[2,3],[3,0]] }`（直穿、2/2 斜纹）。
  `shaftOf(end)` = 该经线穿在第几片综框；`warpOver(end, pick)` = 这一端在这一针是否压在上面。
- `scene.ts`：四片综框按 `DRAFT.rows[picks % 4]` 提升；只有被选中的那两片抬 `22 px`。
- `textile.ts`：布面每一格 `over = warpOver(end, weftLine)`——抬起的经线压在上面，其余是纬线压上。
  **改 draft，布面纹样随之改变**；每根 2 px 纬线推进一次开口，所以斜纹是真正的 45° 对角。
- 工具色只做淡染（34% 混入布底），保持浅色织物；每针仍有一条 0.35 alpha 的纬线发丝。

验证：`node scripts/test-draft.mjs`（已加入 `npm test`）

```
PASS: weave draft — straight draw, 2/2 twill, 50/50 rows, diagonal shift, draft-dependent cloth.
```

测试断言的正是"不是贴图"这件事：每针恰好抬起 draft 指定的两片；抬起的端必然压纬；
每行恰好 50% 在上；相邻两针的纹样错开一根（斜纹对角）；**换一份 draft 布面必然不同**；
plain weave（两片）也能正确展开。

已知简化：真提花是逐针选针（112 端可以各自独立），我们用 4 片综框分组（每 28 端一组）
来近似——这是四片综框织机能表达的最大自由度，也是编织课里的"直穿"。要更接近提花，
需要把综框换成逐端选针的数据结构（布面同样能直接生成），但视觉上会失去综框横梁。
