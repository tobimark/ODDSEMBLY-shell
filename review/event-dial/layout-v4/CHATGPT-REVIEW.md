# 给 ChatGPT 的评审说明（layout v4）

## 0. 一句话

这是 KunlunMeta「Loom 事件转盘」场景的当前版本：在 **1472×1008** 设计空间里安排
**齿轮机械 / Loom 主体 / 12 槽转盘 + 固定读数器** 三块，并按 CrommaCode 外围壳的
真实 GameView 尺寸（约 **730×548** 可见区）控制比例；请评审静态构图、装配关系与可读性。

## 1. 项目背景

- Loom 是一个 Agent 活动可视化装置：工具调用（Read/Bash/Edit/Write/Search）驱动织机、
  12 槽索引转盘与固定读数器。
- 设计空间 1472×1008；PixiJS 渲染；外围是已复刻的 CrommaCode 壳（1453×865 舞台）。
- 本轮**不改进**事件时序、工具颜色、织机金属结构；只改构图、装配与比例。

## 2. 这轮为什么改（按评审反馈）

### 2.1 先修读数器

上一版读数器放在共享床身上，评审指出：

- 读数器旋转/像远程面板；
- 与 40° 读头之间靠长线缆联系；
- 巨型蓝色卡窗和读数器形成两个竞争的“显示装置”；
- 左下控制箱、队列牌、长导线、夹块太多，遮挡主体；
- Loom 被缩小、右移，主体性不足。

处理：

1. 读数器改成**盘面上的固定矩形**，水平、不旋转；只保留 `TYPE / ×N / Sxx / 12`。
2. 读数器从床身移到转盘可见弧带内，用固定蓝弧上的两个夹具 + 一根短连杆悬挂。
3. 删除左下控制箱、队列牌、接线盒、长信号线、读头导管；队列数据仍保留在遥测。
4. 降低巨型卡窗填充，当前槽只留极浅叠色 + 2.4px 工具色边。
5. 转盘减负：夹块 4→2、去掉外圈螺栓阵/轮缘接缝、刻度放稀、读头只留座/臂/读数窗口/定位缺口。
6. 恢复 Loom 主体尺寸。

### 2.2 再解决“三块互相遮挡”

评审后用户又指出：

- 12 槽转盘被 Loom 遮掉太多；
- 齿轮和它背后的驱动箱贴住 Loom；
- Loom 右缘被右侧 Agent 面板挡住；
- 底部留白过大。

处理：

- 转盘整体缩到 **0.83**，只保留左上可见弧带（x 0–470），右侧不再压 Loom。
- 齿轮、飞轮、张力表、驱动箱、电机**整体左移 60px**，作为独立的 outboard 驱动单元；
  驱动箱右缘 407，与 Loom 左框 484 留 **77px**，两根安装 rail 跨过间隙。
- Loom 设为 **1.1×**，左框 484、右缘 1459；在 730 宽显示里右缘约 724/730，
  **主框不再进入 Agent 面板下方**（最右 servo 文字可能贴画布边）。
- 场景按 **fit-width** 放入 GameView：1472×1008 → 730×500（×0.496），
  顶部贴模式栏，底部到 stage y≈640；HUD 上沿 668，只留 **28px**。
  旧版底部约 100px 的空带消失。

## 4. 当前结果

- 三块对象**无像素级重叠**：DIAL 在左上，GEAR 在左下，LOOM 在右侧。
- 齿轮箱与 Loom 之间 **77px** 间隙，且有两根 rail 说明“仍是同一台机器”，不是断开的零件。
- Loom 主框完整可见，不藏在 Agent 面板后；右缘只剩约 6 CSS px 余量。
- 底部不再有旧版约 100px 的空带，HUD 上方留 28px 呼吸。
- 读数器固定、水平，只显示工具/×N/槽位；在 730 宽下主字 18px、次字 9px。
- 事件时序、工具色、30° 步进、×N 不推轮、12 槽回绕均未改；`npm test` 11 条、
  `review:dial` 11 状态通过。

## 5. 已知取舍 / 请重点看

1. **Loom 右缘只剩 13 设计 px（约 6 CSS px）**。为了填掉底部空白，Loom 设到 1.1；
   如果评审认为右侧太挤，建议降到 1.08（左框仍 484，齿轮间隙约 67）。请判断哪个优先。
2. **齿轮箱左移后，箱体与 Loom 左框之间的 77px 间隙**是否足够读成“独立驱动单元”？
   两根 rail 是否够，还是需要把 rail 改成一根显眼的传动轴/护罩？
3. **齿轮箱与飞轮/齿轮的相对位置**：现在 60px 左移后，皮带、表针已重新对齐；
   是否还有“箱体被硬挪走”的感觉？
4. **底部 28px**：是保留 HUD 呼吸，还是继续压到 0（把场景再下移 15px，但顶部模式栏
   与画面之间会出现同等空白）？
5. **读数器**：210×94、无标题、TYPE 44 / 第二行 22；在 730 宽下是否还像网页卡片？
   两个蓝弧夹具 + 短连杆是否足以说明它属于转盘？
6. **转盘可见度**：缩到 0.83 后只露左上弧带；是否足够读出“12 槽、40° 读头、固定读数器”？
7. **整体第一眼**：是否先看到 Loom，再看到转盘，再看到齿轮组？还是仍然平？

## 6. 评审输出格式

请按 **P0 / P1 / P2** 分级，每条给出：

- 问题 + 判断依据（引用图/区域）；
- 具体改法（设计 px、尺寸、线宽、字号、层级/遮挡关系）；
- 是否会破坏以下硬约束，以及代价。

最后给 **不超过 6 条**的静态构图最小改动清单，按执行顺序排。

## 7. 硬约束

1. 读数器结构上不可旋转、文字水平，不能放进转子容器。
2. 读数器不能回到底座/共享床身/独立远程面板。
3. 12 槽、30°/格；卡窗中心最终落在 40° 读头下。
4. 同工具事件就地 ×N，不推轮；稳态零运动。
5. 不改工具色板、事件时序。
6. 盘心在画布外、只露左上弧段是刻意裁切。
7. 不为了“机械感”新增控制台、灯带、粒子或大面积装饰。
