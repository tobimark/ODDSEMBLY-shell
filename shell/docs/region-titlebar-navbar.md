# 区域文档 — 标题栏 TitleBar + 导航条 NavBar

owner：chrome-bar
文件：`src/regions/TitleBar.tsx`、`src/regions/NavBar.tsx`
参考帧：`.tmp/shell/ref.png`（2906×1730，200% DPI）

> **状态提醒（合并前必读）**
> - `TitleBar.tsx` = 初版作者的实现：**weight 400 + `-webkit-text-stroke`** + 手绘 `win-*` 三键。实测 `title_bar = 1.85~1.96`，是当前最优，保留。
>   ⚠️ stroke 值：初版是 **0.16px**，磁盘现状（23:23 后被并发 agent 改成）**0.20px**；5 档网格搜索显示 0.18/0.26/0.34 差异 ≤0.06（噪声地板），0.16 与 0.20 等价。
> - `NavBar.tsx` = **我（titlebar/navbar 校准）的实现**：`Glyph` + `ASSET_INK` 按"资产内部 ink 矩形"反解 size、`Label` 默认 **weight 600（SemiBold）+ letter-spacing 压缩 advance**、**无 text-stroke**、`PanelGlyph` 按逐行 dark-run 重描、所有图标**等比**缩放（非等比拉伸实测更差，已弃用）。
>   **实测 `nav_bar = 2.33`（连拍 3 张稳定）**，优于初版作者的 `400 + stroke 0.16` 版本（`nav_bar = 2.82`）→ 以像素分为准，采用并发版本。
> - 两条**文字墨量补偿路线**结论相反，本文 §6/§8 把两条都记下来，**不要合并成一条结论**。
> - 本文所有坐标/颜色/字号都来自参考帧实测，与谁实现无关，可直接作为唯一标准。

## 6. 字体渲染：参考帧比我们"重"，这是文字区误差的地板

同一 ink 框、同字号、同颜色下，参考帧的墨量比 headless Chromium 的灰度 AA 重 **11–14%**：

| 区域 | ref sumInk | 无补偿 | +0.1px stroke |
|---|---|---|---|
| CrommaCode | 375.5 | 332.4（−11.5%） | 353.5（−6.2%） |
| 6 个菜单 | 931.7 | 815.8（−12.4%） | 876.4（−6.0%） |
| 终端+Ctrl+J | 267.7 | 236.5（−11.7%） | 251.4（−6.1%） |

补偿手段：`-webkit-text-stroke: <w> currentColor`（不改 advance / 不重排）。`w = 0.16px` 时实测 title_bar 2.24 → **1.85**；磁盘现状是 0.20px（网格搜索里 0.18→1.913、0.26→1.920、0.34→1.974，与 0.16 同属噪声地板）。

## 7. 阴影带（native y 189..212，x 543..2874）：二维，不是竖向渐变

逐行 + 逐 50px 列采样后的结构：

| x 区间 | native 行为 | 说明 |
|---|---|---|
| 543..700 | 平亮 `#fcfaf6 → #fbf9f5` | 无阴影 |
| 700..843 | 水平渐入 | y189 `#faf8f4` → y212 `#f1f0eb`（越往下越暗） |
| 843..1743 | 全阴影 | 竖向 `#f8f6f2 → #f0eeea`；含两条更深窄带（中心 ≈ native 1093 `#ebe8e3`、1493 `#e8e5e1`，各约 100px 宽）|
| 1743..1893 | 水平渐出 | → `#fbf9f5` |
| 1893..2874 | 平亮 `#fbf9f5/#fcfaf6` | 无阴影 |

两种实现（等价级）：
1. 平底 + 带水平遮罩的竖向渐变层（本文 §3 之前版本）；
2. 单一层：竖向渐变 `#eeece6 → #e6e4df` × 67 点实测 alpha 遮罩（当前磁盘 `NavBar.tsx` 用的就是这种，注释里写 modelled abs error 1.4 vs 2.9）。
逐行/逐列残差应 < 1.5 级；这一块在 `nav_bar` 里原本约占 1/3 误差（3.05 × 35/102）。

## 8. 已验证排除的路线（别重复踩）

| 路线 | 结果 | 数据 |
|---|---|---|
| **开启 LCD 子像素 AA**（`SHOOT_LCD=1` → `--enable-lcd-text`） | ❌ 更差 | CHROME 1.87→1.90、sidebar 3.25→3.33、title 1.96→1.96。参考帧确实是 ClearType（墨迹色度 50 vs 我们 12，最大 163），但 **headless Chromium 的 LCD 相位与 GPUI/DirectWrite 不同源**，只增加逐通道彩边误差。 |
| **font-weight 600（SemiBold）+ letter-spacing 压缩** | ✅ 在 `nav_bar` 上**实测更优**（与理论相反） | 参考帧 ink 外框由 400 1:1 复现（CrommaCode 176×22 = 176×22），`fontmatch` 400 得 0.963–0.980 —— 但像素分是唯一裁判：**600 + 字距压缩 = nav_bar 2.33**，`400 + stroke 0.16` = **2.82**（连拍 3 张稳定）。机理：`text-stroke` 是**等向外扩**（字腔变窄、边缘整体外移 ~0.1px），而 600 是**轮廓本身更粗**、字腔比例更接近参考帧。→ 导航条采用 600 路线；标题栏仍是 400+stroke（1.85~1.96，未测过 600，不要擅自替换）。 |
| **text-shadow 光晕** | ❌ | 半透明光晕降低边缘对比，方向与"变重"相反（icon-mapper 独立验证）。 |
| **只做 bbox 对齐（不加墨量补偿）** | ⚠️ 不够 | 全部元素 dx=dy=0 后，纯文字区仍停在 10–11 meanAbs（`tb_menus 11.13`、`tb_wordmark 10.60`）；因为差异来自栅格化而非几何。 |
| **继续细调 stroke 宽度** | ⚠️ 二阶效应 | 5 档网格搜索：title 0.18→1.913 / 0.26→1.920 / 0.34→1.974；sidebar 0.26→2.569 / 0.34→2.559 / 0.42→2.642。差异 ≤0.06–0.08，已在 AA 噪声地板内。 |

## 10. 未做到 / 不确定

1. **文字区的残差是栅格化差异**，不是几何/字号/颜色问题：dx=dy=0、最暗像素逐通道一致，仍剩 10–11 meanAbs。除非换渲染后端，否则是地板。
2. **右端最后一个图标的语义**不确定（见 §9 `ticket`）。
3. **`eye`**：参考 ink 15×12，资产 artwork 15×11 → 需要纵向拉伸 8% 或 size 16.5；两种做法都在用，未定论。
4. **阴影带**的两条更深窄带（native 1093 / 1493，各 ~100px）在简化模型里没有单独画，残差 <1 级。
5. **hover / active** 未实现：静态截图无依据，宁缺勿造。
6. **`nav_bar` 右侧 chrome 槽 x 1431..1440** 不属于本区域，未处理。
7. **两套 ink 表混用会引入 ±1 native 系统偏差**：并发版本的 `ASSET_INK`（`lock.t=0.6/h=14.5`、`clock 15.5×15.5`…）与本文 §2/§3 的 ref 实测 ink（`lock 11×14`、`clock 14×14`）不完全一致。合并时**以本文的 ref 实测表为准**，不要两套混用。
8. **两条文字墨量路线**（`400+stroke` / `600+字距`）在指标上各有胜负，见 §8；`NavBar.tsx` 是 600 路线，`TitleBar.tsx` 是 400 路线，**同一份 UI 里两种墨量补偿方式并存**，如果以后要统一，必须在整页范围内重测（局部最优 ≠ 全局最优）。

### 12.1 改了什么

`NavBar.tsx`（改动最大）：

1. **图标按"墨迹框"定位，不再一律 16px**。新增 `ASSET_INK`（每个图标在 16 网格里
   的墨迹矩形，本 build 实测），`Glyph()` 用「目标墨迹框」反解 `size` 与盒子位置。
   实测参考帧的图标墨迹普遍比我原来的 16px 小 **10–14%**（lock 10.5×13.5、gauge
   14×11.5、file-text 10.5×12.5、bot 13.5×12、clock 13.5×13.5、trophy 11.5×11.5、
   terminal 12.5×11.5、eye 15×12、waveform 12.5×11.5、volume 15.5×12.5）。
   **必须等比缩放**：按 x/y 两轴分别非等比拉伸会把 artwork 压扁，实测更差（我试过，
   file-text/trophy/terminal 三个被压扁后 nav 从 2.31 退化到 2.38）。
2. **`git-fork` → `glyph-fork`**。参考帧那一格是「两上点 + 左下点 + 竖干 + 右弧」，
   `uiIcons['git-fork']` 是三个大圆环 + T 形连接，形状完全不同（这一格曾占右端
   5 图标误差的 50%）。`uiIcons['glyph-fork']` 才是同一图形。
3. **文字一律 weight 600 + 字距压缩**（见 §6 的同一个结论，独立验证）：
   15px CJK 标签 `letterSpacing 0`（advance 36 native 本来就对）、`终端` 13px 的
   `letterSpacing` 由 +1px 改为 **−0.5px**（实测 advance 30 native，之前 +1 让
   第二个字右移 4 native，是那一格最大的误差源）、`Ctrl+J` 保持 12.5px/400。
   in-situ A/B：400 → nav 2.784、600 → 2.380、700 → 2.393。
4. **阴影带改成 rank-1 模型**：`background` = 竖向 ramp（4 stops，
   从最深一列实测 `#eeece6→#e6e4df`），`mask-image` = 横向实测 alpha
   （67 个 10px stop，`SHADOW_ALPHA`）。参考帧这条带只在 client x 265..930 存在，
   并且有两个更暗的竖条（client ~555 / ~755），平铺整幅是主要误差来源。
   该带误差 176 498 → 66 059（meanAbs 3.15 → 1.18）。
5. 选中药丸投影 `0 1.5px 4px rgba(26,21,15,0.16)`（参考帧下方 6.5px 仍有 1–3 级暗）；
   胶囊圆角 7 → **9**（角部 border 剖面 1219→1234 的下降曲线拟合出 r≈9）：
   终端药丸左移 0.5px。
6. 根 div 不再铺 `#fcfaf6`（改用 App 的 `.surface`），符合 Lead 的要求。

`TitleBar.tsx`：菜单 **weight 600 / letterSpacing −0.4**、字标 **weight 600 /
letterSpacing −0.1**、**去掉 text-stroke**（stroke 会让墨迹纵向多 1 native px）。
in-situ A/B（strip meanAbs）：`400+stroke0.20` 1.807 → `600 ls−0.5` 1.607 →
`600 ls−0.5 无 stroke` 1.373 → `600 ls−0.4 无 stroke` **1.326**。

### 12.3 仍然解决不了的（诚实清单）

1. **文字 AA 是地板**：参考帧是 GPUI/Skia 的**次像素（LCD）AA**（每根竖笔都有
   `#2A476F`/`#CC9043` 这类 RGB 边缘），我们的截图走 `--disable-lcd-text` 灰度 AA。
   现在菜单的墨迹框已经和参考帧**逐像素对齐**（x336..579 y40..64 完全一致），
   残差 100% 是 AA 分布差异。继续调 weight/字距/stroke/blur 只会变差
   （0.25px 文字阴影 → 1.554、0.4px → 1.627）。
2. **右端最后一个「面板」图标是手描 `PanelGlyph`**，但已按参考帧的真实几何重画：
   外框上/下边水平、左右边为**内凹弧**（边框中心线向里鼓 2px），中缝是**虚线段
   （1/2/1 css，间隙 1px）**。依据是逐行 dark-run 实测（y137..158、x2822..2851）。
   该格误差 15.9 → 13.4，是全 nav 最后一块手绘字形。`uiIcons['glyph-frame']`
   是竖版 9×12，不是它。
3. **品牌标记的光线透明度与参考帧不一致**：参考帧最上面那道竖光线更暗
   （native(67,26) 参考 `#DAD5CE` / 我们 `#E8E3DD`），而左下斜光线参考更浅。
   `brand.tsx` 的 fill-opacity 组合（1/0.9/0.8/0.4/0.3/0.2/0.1）与参考帧对不上，
   但 brand 整体只剩 6.5k（1% ），且 `src/svg/brand.tsx` 不归我改。
4. **窗口 3 个按钮**（icon-mapper 的 win-* 向量）另有 58k 误差：关闭 +1 native 宽、
   最大化 +2 native 宽 +1 高，属 `src/svg/uiIcons.ts` 资产，不在我能改的文件里。
5. 图标还剩若干 **±1 native px**（0.5 css）的墨迹偏差（clock/file-text 高度、
   eye 宽 +1、排行榜首字 +1），已在 5.1% 的 %>8 里；继续修收益 <0.01。
6. `test` 项目名、`Ctrl+J` 这类拉丁小字同样在 AA 地板上（墨迹框完全一致）。
